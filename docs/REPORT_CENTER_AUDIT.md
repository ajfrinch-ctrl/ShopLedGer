# রিপোর্ট সেন্টার — অডিট ও সংশোধন

তারিখ: ১৯ সেপ্টেম্বর ২০২৬

## পরিধি

রিপোর্ট সেন্টারের ১০টি রিপোর্ট, রেঞ্জ/বিষয়ভিত্তিক ফিল্টার, শাখা ও রোল-স্কোপ,
প্রিভিউ, A4 শিট, PDF/ছবি এক্সপোর্ট এবং শেয়ার টেক্সটের কোড পর্যালোচনা করা হয়েছে।
এটি কোড ও পরীক্ষামূলক ডেটার অডিট; ব্যবহারকারীর প্রকৃত ব্যবসায়িক রেকর্ডের স্বাধীন যাচাই নয়।

## সমস্যা ও সংশোধন

| সমস্যা | সংশোধন |
| --- | --- |
| নির্বাচিত রিপোর্টের ফিল্টার সব কার্ডের নিচে ছিল | কার্ডে ট্যাপেই viewport-এর মধ্যে রেঞ্জ ডায়ালগ। পেছনের পৃষ্ঠা স্ক্রল বন্ধ; কোনো `scrollIntoView` নয়। |
| পুরোনো দ্রুত সারসংক্ষেপ নতুন রিপোর্টের সঙ্গে মিশে যাচ্ছিল | অব্যবহৃত `QuickSummary` UI সরানো হয়েছে। সেন্টারের স্টেটমেন্টে সারি, প্রাসঙ্গিক মোট ও হিসাবের ব্যাখ্যাই থাকে। |
| ক্রেতার বাকিতে supplier ledger ঢুকছিল | শুধু সক্রিয় customer ledger অন্তর্ভুক্ত। বাতিল, অন্য শাখা ও শেষ তারিখের পরের এন্ট্রি বাদ। |
| রেঞ্জের বাকি বিক্রি/আদায় দিয়ে সমাপনী বাকি ব্যাখ্যা করা যাচ্ছিল না | প্রারম্ভিক বাকি + চলতি সময়ে পুরোনো বাকি যোগ + বাকি বিক্রি − আদায় = সমাপনী বাকি। অগ্রিম জমাও রাখা হয়। |
| একজন ক্রেতা বাছলেও কেবল সমষ্টিগত সারি | ক্রেতা বাছলে তারিখক্রমে প্রারম্ভিক সারি, বিক্রি/আদায় ও চলতি ব্যালেন্সসহ হিসাব বিবরণী। |
| বিক্রির item total ডিস্কাউন্টের পরের bill total-এর সঙ্গে মিলছিল না | বিলের মোটকে ভিত্তি করে পণ্যের অনুপাতে ছাড়/সমন্বয় বণ্টন; পয়সার cumulative rounding। পণ্য ফিল্টারের **আগে** বণ্টন হয়। বিক্রি এবং লেনদেন রিপোর্টে একই লজিক। |
| ভিন্ন এককের পরিমাণ একসঙ্গে যোগ হতো | লিটার, কেজি ইত্যাদির মোট আলাদা এককসহ দেখানো হয়। |
| স্টকের সমন্বয় কলাম ছিল না | ওপেনিং, ক্রয়, বিক্রয়, সমন্বয় ও সমাপনী স্টক আলাদা। অতীতের cutoff-এ ভুল “আজ পর্যন্ত” লেবেল সরানো হয়েছে। |
| পণ্য রিপোর্টে ভবিষ্যতের এন্ট্রিও “বর্তমান” স্টকে পড়ত | নির্দিষ্ট cutoff তারিখের ফিল্টার ও সেই তারিখ পর্যন্ত stock calculation। |
| লাভের রিপোর্টে ক্রয়/আদায়/বাকি/স্টকের অপ্রাসঙ্গিক সংখ্যা; মাসিক ক্রয়ে বিভ্রান্তিকর বিয়োগচিহ্ন | লাভের স্টেটমেন্টে কেবল নিট বিক্রি, বিক্রিত পণ্যের ক্রয়মূল্য, গ্রস লাভ, দোকানের খরচ ও নিট লাভ/ক্ষতি। মালিকের টাকা তোলা বাদ নয়। |
| মিশ্র লেনদেনের সঙ্গে ফিল্টার না-মেলা সামারি | মিশ্র লেনদেনের সম্মিলিত মোট নেই। এক প্রকৃতির নির্বাচিত লেনদেন হলে শুধু মিলিত সারির মোট। Supplier opening-এর জন্য “পুরোনো দেনা” ফিল্টার যুক্ত। |
| শাখার বাইরের category/payment method অপশনে আসত | অপশনেও একই শাখা-স্কোপ; supplier-only payment method বাদ। Ledger/legacy-only ক্রেতা ফিল্টারে পাওয়া যায়। |
| খালি অনুমোদিত শাখার তালিকা সব শাখা হিসেবে ধরা হতো | `branchIds: []` মানে কোনো শাখার অনুমতি নেই। মালিকের সব শাখার জন্য scope `{}` অপরিবর্তিত। |
| ফাঁকা/অবৈধ তারিখে অনিচ্ছায় all-time হিসাব | UI ও builder দুই স্তরে তারিখ, মাস ও রেঞ্জ যাচাই। অবৈধ হলে তৈরি বোতাম নিষ্ক্রিয়। |
| ৫০০ সারির পরে তথ্য বাদ, কিন্তু মোট সব ডেটার | Builder-এর সারি সীমা সরানো। প্রিভিউতে ১০০ সারির নেভিগেশন; সব সারি পাওয়া যায়। |
| সম্পূর্ণ লম্বা রিপোর্ট এক বিশাল canvas-এ ক্যাপচার | ২৪ সারির A4 capture block; একবারে একটি block ক্যাপচার। হেডার পুনরাবৃত্তি, মোট/স্বাক্ষর শেষে, ধারাবাহিক পৃষ্ঠা নম্বর। টেবিলের row boundary ধরে page break। |

## JavaScript / interaction

- প্রতিবার টাইপে সব রিপোর্ট পুনর্গঠন নয়: “স্টেটমেন্ট দেখুন” চাপলে snapshot তৈরি।
- নতুন report kind-এর keyed session-এ পুরোনো ফিল্টার/প্রিভিউ ঢোকে না।
- প্রিভিউ বন্ধ করলে নির্বাচিত রেঞ্জ অক্ষত থাকে। শাখা বদলালে পুরোনো শাখার entity filter সাফ হয়।
- ডায়ালগে Escape, Tab/Shift+Tab focus containment এবং `preventScroll` দিয়ে আগের কার্ডে focus ফেরানো হয়।
- PDF/ছবি তৈরির সময় প্রিভিউ বন্ধ করা নিষ্ক্রিয় থাকে।
- বাংলা সংখ্যার `Intl.NumberFormat` পুনর্ব্যবহার করা হয়।
- এক্সপোর্ট শেষে canvas এবং PDF library timeout timer পরিষ্কার করা হয়।
- কার্ডে ট্যাপ বা প্রিভিউ খোলার ফলে স্বয়ংক্রিয় ডাউনলোড হয় না।

## যাচাই

- `npm test`: **৭৪ পাস, ০ ব্যর্থ**। Discount rounding, ৬০১ সারি, supplier exclusion,
  opening/closing balance, customer ledger, mixed units, cutoff, invalid range,
  branch scope ও role catalog regression অন্তর্ভুক্ত।
- `npm run test:ui`: **৬৫ পাস, ০ ব্যর্থ**। DOM-ভিত্তিক integration smoke:
  কার্ড → রেঞ্জ → প্রিভিউ → আগের রেঞ্জ, focus/scroll lock, Escape,
  দৈনিক/মাসিক ফিল্টার, ৬০১ সারির pagination, A4 block completeness, প্যাড ও বিদ্যমান রসিদ।
- `npm run lint`: পাস।
- `npm run build`: পাস। Vite-এর ৫০০ kB-এর বেশি bundle সতর্কতা এখনও আছে।
- dependency audit (`npm ci`): ০ known vulnerability।

## সীমা / হাতে যাচাই বাকি

- বাস্তব Chromium পরীক্ষার জন্য browser download চেষ্টা করা হয়েছে, কিন্তু sandbox-এর
  CDN/TLS সংযোগ ব্যর্থ হয়েছে। ফলে mobile pixel layout, বাস্তব PDF/JPEG rasterization,
  ফন্ট এবং OS/WhatsApp share sheet হাতে যাচাই বাকি। DOM smoke-কে visual/browser test বলা হচ্ছে না।
- স্টক মূল্যায়ন বর্তমানে সংরক্ষিত product price দিয়ে হয়; historical price snapshot নেই।
  রিপোর্টের নোটে এ সীমা স্পষ্ট। Product opening stock-ও মডেলের undated initial value।
- একই collection পুরোনো collection table ও ledger-এ স্বাধীনভাবে সংরক্ষিত থাকলে matching
  migration key ছাড়া নিরাপদ deduplication সম্ভব নয়; বিদ্যমান source semantics রাখা হয়েছে।
- খুব লম্বা বিবরণ একটি A4 পৃষ্ঠার চেয়েও উঁচু হলে এক সারি ভাঙতে হতে পারে।
- রোল-স্কোপ অ্যাপের local report layer-এ প্রয়োগ করা হয়েছে; এটি backend authorization audit নয়।
