# বাকি ও পরিশোধের খাতা

## ব্যবহার
- নিচের **বাকি খাতা** থেকে ক্রেতা বা সাপ্লায়ার নির্বাচন করুন। সব শাখার বিল ও লেনদেন একসঙ্গে দেখানো হয়।
- পুরোনো বাকি যোগ করা যায়। নতুন ক্রেতার পুরোনো বাকি যোগ করলে সেই ক্রেতা বিক্রয় ফর্মেও পাওয়া যাবে।
- আদায়/পরিশোধের শাখা নির্বাচন করুন। কর্মীরা নিজের শাখায়, মালিক যেকোনো সক্রিয় শাখায় লেনদেন করতে পারেন। দেনা কোন শাখায় হয়েছিল তা পরিশোধকে সীমাবদ্ধ করে না।
- নগদ টাকা, ব্যাংক, বিকাশ, নগদ মোবাইল ব্যাংকিং সমর্থিত। রেফারেন্স ও মন্তব্য ঐচ্ছিক।
- অগ্রিম সমর্থিত নয়। বর্তমান বা পূর্বের তারিখে কোনো পর্যায়ের ব্যালেন্স ঋণাত্মক হলে সেভ প্রত্যাখ্যাত হয়। একই দিনের বিল/পুরোনো বাকি আগে, তারপর আদায়/পরিশোধ তৈরির ক্রমানুসারে দেখানো হয়।
- মালিক এবং সংশ্লিষ্ট শাখার কর্মী কারণসহ এন্ট্রি সংশোধন/বাতিল করতে পারেন। বাতিল এন্ট্রি মুছে যায় না। ইতিহাসে ব্যবহারকারী, সময় এবং আগের/পরের তথ্য থাকে।
- **আরও / শাখার প্যাড** থেকে মালিক শাখা তৈরি ও প্রতিষ্ঠানের নাম, লোগো, ঠিকানা, ফোন নির্ধারণ করতে পারেন।
- রসিদে প্রিন্ট, PDF ও PNG ডাউনলোড আছে। ছবি তৈরির পর শেয়ার বাটনে WhatsApp বেছে নেওয়া যায়, যদি ব্রাউজারের ফাইল শেয়ার সমর্থন থাকে। অন্যথায় ডাউনলোড করা ছবি WhatsApp-এ সংযুক্ত করতে হবে।

## ডেটা ও সীমা
- বিদ্যমান অ্যাপের মতোই স্থানীয় ব্রাউজার স্টোরেজ ব্যবহৃত হয়। খাতা/অডিট/প্যাড IndexedDB-তে; বিক্রয় ও ক্রয় বিদ্যমান Zustand/localStorage-এ। একই ব্রাউজারের সব শাখা একত্র হয়, **আলাদা ডিভাইস/ব্রাউজারের মধ্যে সিঙ্ক নয়**। উৎপাদন পর্যায়ের বহু-ডিভাইস ব্যবহার ও নিরাপদ অনুমতির জন্য সার্ভারভিত্তিক লেনদেন, অথরাইজেশন ও সিঙ্ক প্রয়োজন। স্থানীয় অডিট সার্ভার-সুরক্ষিত বা tamper-proof নয়। ব্রাউজারের ডেটা মুছলে হিসাব হারাবে।
- IndexedDB v1 → v2 আপগ্রেডে পুরোনো টেবিল অক্ষত থাকে। পুরোনো collections পড়া হয়, পুনরায় কপি করা হয় না।
- পুরোনো ক্রয়ে নগদ/বাকি তথ্য ছিল না; সেগুলো স্বয়ংক্রিয়ভাবে বকেয়া নয়। যাচাই করে প্রারম্ভিক বাকি দিন। নতুন ক্রয়ে নগদ/বাকি নির্বাচন করুন।
- বর্তমান ক্রয় মডেলে সাপ্লায়ার ID নেই। Unicode-normalized, trimmed, whitespace-collapsed, lowercase নাম দিয়ে সাপ্লায়ার একত্র হয়। একই সাপ্লায়ারের জন্য একই নাম ব্যবহার করতে হবে; সমনামের আলাদা প্রতিষ্ঠান থাকলে পৃথক নাম ব্যবহার করুন।
- প্যাড বর্তমান সেটিংস দিয়ে রেন্ডার হয়; পুরোনো রসিদের immutable pad snapshot নয়।
- আদায় থাকা ক্রেতার বাকি বিক্রয় বিল মুছতে বাধা দেওয়া হয়, যাতে খাতায় অসামঞ্জস্য না হয়। পুরোনো সংগ্রহের জন্য এ সংস্করণে সম্পাদনা UI নেই।

## যাচাই
```
npm ci --legacy-peer-deps
npm test
npm run build
```
বিদ্যমান Vite 8 / React plugin 4 / PWA plugin 0.20 peer dependency অসামঞ্জস্যের জন্য ইনস্টলে `--legacy-peer-deps` প্রয়োজন। বিল্ড সফল হলেও plugin compatibility এবং chunk-size সতর্কতা আছে।

স্বয়ংক্রিয় পরীক্ষায়: cross-branch আদায়, partial payment, অডিট, বাতিল, overpayment, backdating, role/branch permission, decimal precision, concurrent payment এবং v1 database upgrade অন্তর্ভুক্ত। প্রিন্ট, PDF এবং WhatsApp শেয়ার বাস্তব ব্রাউজার/ফোনে যাচাই করতে হবে।
